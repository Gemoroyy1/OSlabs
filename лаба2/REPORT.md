# Работа 2 Управление памятью

## Цель
Исследовать виртуальное адресное пространство процесса Windows и обмен данными между процессами через отображение файла в Linux.

## Задание 2.1
Создано консольное приложение с отдельными пунктами для GetSystemInfo, GlobalMemoryStatus, VirtualQuery, резервирования, фиксации страниц, совместного резервирования и фиксации, снятия фиксации, освобождения, записи байта и VirtualProtect. Для автоматического размещения передаётся nullptr; для заданного адреса вводится число. Последний адрес выделения выводится пользователю.

Резервирование MEM_RESERVE занимает диапазон виртуальных адресов, но не делает его доступным для записи. MEM_COMMIT обеспечивает обязательство системы предоставить хранилище страниц; это не означает, что все страницы немедленно находятся в физической RAM. Снятие фиксации MEM_DECOMMIT возвращает страницы в RESERVED; MEM_RELEASE освобождает весь исходный регион. Резервирование округляется по гранулярности выделения, фиксация — по размеру страницы.

GlobalMemoryStatus используется согласно методичке, но имеет исторические ограничения типов; для современных прикладных программ предпочтительнее GlobalMemoryStatusEx. VirtualQuery показывает регион с одинаковыми свойствами, а не содержимое памяти.

### Проверки 19.10.2026
Компилятор MinGW g++, Windows x64. Полный протокол windows-tests.txt. Заданный адрес 0x20000000000, резервирование 8192 байта, фиксация первых 4096 байт.

| Операция | Фактический результат |
|---|---|
| Резервирование и VirtualQuery | MEM_RESERVE, State=8192 |
| Фиксация и запись байта 65 | Byte written |
| VirtualProtect READONLY | Проверенная защита 2 |
| Попытка записи после READONLY | Ошибка Win32, процесс продолжил работу |
| MEM_DECOMMIT и запрос | MEM_RESERVE |
| MEM_RELEASE и запрос | MEM_FREE, State=65536 |

Запись сделана через WriteProcessMemory текущего процесса: защищённый/неверный адрес приводит к контролируемой ошибке API вместо необработанного access violation. Изменение защиты проверено VirtualQuery.

## Задание 2.2
Созданы два отдельных исполняемых файла из shared.cpp: server с макросом SERVER и client без него. Сервер создаёт файл O_EXCL, увеличивает до 4096 байт через ftruncate и отображает через mmap MAP_SHARED с PROT_READ|PROT_WRITE. Клиент открывает существующий файл только для чтения и отображает с PROT_READ. Существующий файл не перезаписывается. Все ветви завершают работу через munmap, close и sem_close; сервер также вызывает unlink и sem_unlink.

Сервер копирует строку с завершающим нулём в общую память, подаёт ready и ожидает read. Клиент ожидает ready, считывает строку ограниченной длины, выводит её и подаёт read. После подтверждения можно завершить оба приложения через меню; сервер удаляет файл. Данные не передаются через семафоры: они служат только для синхронизации. select обычного файла не позволяет определить появление нового сообщения, поэтому его использование здесь заменено семафорами.

Предусмотрены три пункта в каждом меню: отображение, запись/чтение, завершение. Операция до отображения отклоняется. Приложения предназначены для одного писателя и одного читателя, аварийное восстановление и тайм-аут ожидания не реализованы.

### Проверки
Ubuntu 24.04, WSL2, g++ C++17. test_exchange.py запускает реальные отдельные процессы и проверяет подтверждение серверу, точное содержимое строки и отсутствие файла после завершения. Проверены Hello, shared memory!, кириллица «Серов И.С. группа 4312» и пустая строка. Полный протокол linux-tests.txt.

## Выводы
Виртуальное адресное пространство отделяет резервирование диапазона от фиксации страниц. Состояние и права региона можно наблюдать VirtualQuery; READONLY действительно предотвращает запись. Освобождение региона отличается от снятия фиксации.

Отображение MAP_SHARED позволяет процессам обращаться к одним файловым данным, но само по себе не создаёт протокол готовности. Для корректного обмена необходимо явно согласовать доступность сообщения и окончание чтения. Два семафора обеспечивают такой порядок, а удаление файла после завершения сервера предотвращает накопление временных данных при штатной работе.
