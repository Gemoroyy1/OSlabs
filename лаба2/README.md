# Работа 2 Управление памятью

Язык C++17. Задание 2.1 — Windows, задание 2.2 — Linux по уточнению методички.

## Windows
```powershell
g++ -std=c++17 -Wall -Wextra memory_win.cpp -o memory_win.exe
.\memory_win.exe
```
Адреса и маски можно вводить как 0x...; размеры — в байтах. 0 при резервировании означает автоматический выбор адреса. Программа выводит адрес последнего выделения: использовать его для дальнейших операций. Для MEM_RELEASE указывается начальный адрес резервирования, размер передаётся равным нулю. После READONLY запись должна завершиться ошибкой; приложение использует WriteProcessMemory для проверки без аварии процесса.

## Linux
```bash
mkdir -p build
g++ -std=c++17 shared.cpp -DSERVER -pthread -o build/server
g++ -std=c++17 shared.cpp -pthread -o build/client
./build/server
# в другом терминале
./build/client
```
1. На сервере выбрать 1 — создать и отобразить файл.
2. На клиенте выбрать 1 — открыть и отобразить файл.
3. На клиенте выбрать 2 — ожидать данных.
4. На сервере выбрать 2 и ввести строку — сервер ждёт подтверждения.
5. Клиент выводит данные и подтверждает чтение. Выбрать 0 на клиенте и сервере; сервер отменяет отображение и удаляет файл.

По умолчанию файл /tmp/oslab2-shared.bin и имена семафоров /oslab2-ready, /oslab2-read. Аргументы: путь файла и префикс семафоров (одинаковые в обоих процессах). Клиент запускается после создания отображения сервером. Размер файла 4096 байт, максимум 4095 байт текста. После аварийного завершения могут остаться файл и семафоры; штатное завершение освобождает их. Ожидание без тайм-аута: при отсутствии второго процесса требуется прерывание пользователем. Один сервер и один клиент, одинаковые имена для одной сессии.

Автотест: `python3 test_exchange.py` (три отдельных пары процессов).

`select` для обычного файла не является уведомлением о новом сообщении: такой дескриптор обычно сразу готов к чтению. Поэтому доступность данных и факт прочтения передаются POSIX-семафорами; полезные данные передаются исключительно через mmap MAP_SHARED. Это обеспечивает порядок «запись → чтение → подтверждение → освобождение».
