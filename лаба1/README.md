# Работа 1. Управление файловой системой

Исходники: `filesystem_win.cpp` — задание 1.1 (Windows), `aio_copy.cpp` — задание 1.2 (Linux, POSIX AIO). Язык C++17.

## Сборка Windows

```powershell
g++ -std=c++17 -Wall -Wextra -Wpedantic filesystem_win.cpp -o filesystem_win.exe
.\filesystem_win.exe
```

Либо CMake с установленным компилятором: `cmake -S . -B build`, `cmake --build build`.
В меню каждый вызов API вынесен в отдельный пункт. Пути с пробелами вводятся без кавычек. Относительные пути разрешаются относительно рабочего каталога. Для интерактивного ввода кириллицы рекомендуется английский путь или консоль с согласованной системной кодировкой; перенаправление UTF-8 в wide stream MinGW отдельно не поддержано.

## Сборка и запуск Linux

```bash
cmake -S . -B build
cmake --build build
./build/aio_copy input.bin output.bin 65536 4
cmp input.bin output.bin
python3 benchmark.py --exe ./build/aio_copy --mib 64 --repeats 3
```

Файл назначения должен отсутствовать. Скрипт создаёт временные файлы, проверяет границы блоков, пустой файл и все значения параллелизма; затем проводит 90 измерений. `results/measurements.csv`, два SVG-графика и `summary.txt` создаются только после реального запуска. Для исследования размера файла повторить с `--mib 1`, `--mib 16`, `--mib 256`, сохраняя результаты каждого запуска отдельно.

Число операций — верхняя граница одновременно отправленных запросов, каждый слот чередует чтение и запись своего блока. При n=1 чтение и запись последовательны; n=2 позволяет перекрытие чтения одного блока и записи другого. Это не n пар чтения/записи. Данные последнего неполного блока передаются фактической длиной. Кратность проверяется по `st_blksize` (рекомендованный размер I/O, не гарантированный физический размер кластера Linux). `O_DIRECT` не используется, поэтому выравнивание буфера не требуется.

Обработчик `aio_completion_handler` вызывается диспетчером после завершения, уведомления `SIGEV_NONE`; ожидание реализовано `aio_suspend`. Это сознательный вариант без потоковых/сигнальных callback. Он сохраняет POSIX AIO и обработку завершений, но не использует `SIGEV_THREAD`.

Время включает ожидание AIO и `fsync`, но не создание буферов, открытие файлов и проверку. Замеры используют файловый кэш, очистка кэша не выполняется. Оптимум относится только к испытанным настройкам, размеру файла и конкретному компьютеру.
