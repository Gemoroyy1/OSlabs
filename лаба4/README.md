# Работа 4 Межпроцессное взаимодействие

Windows, C++17, студбилет 230616. 16 страниц по размеру GetSystemInfo.dwPageSize.

```powershell
g++ -std=c++17 -O2 -Wall -Wextra rw.cpp -lwinmm -o rw.exe
g++ -std=c++17 -O2 -DSERVER pipe.cpp -o pipe_server.exe
g++ -std=c++17 -O2 pipe.cpp -o pipe_client.exe
.\rw.exe reader 1 demo 3
.\rw.exe writer 1 demo 3
python test_lab.py
python build_report.py
```

rw: роль, ID, уникальное имя сеанса, число циклов. Для совместной работы всем процессам указать одинаковый сеанс; каждый процесс должен иметь уникальные роль/ID. Файл сеанса сохраняется для анализа. Новые опыты используют новые имена. Программа завершает работу с ошибкой, если VirtualLock не выполнен; привилегии для него не повышаются автоматически. После аварии процесс может оставить занятый семафор: аварийное восстановление не реализовано. Читатели имеют приоритет, при бесконечном притоке возможно голодание писателя; тест ограничен тремя операциями на процесс.

Канал: сначала сервер — 1 создать, 2 создать событие, 3 ждать подключения; затем клиент — 1 подключиться, 2 читать. На сервере 4 ввести сообщение. После завершения чтения на сервере 5 отключить, 0 выйти; клиент 0 выйти. По умолчанию \\.\pipe\OSlab4. Можно указать имя канала аргументом; клиенту разрешено передать UNC-имя удалённого сервера при наличии прав и сетевой доступности. Сетевой обмен между разными компьютерами не проверялся. Для синхронизации APC клиент обязательно находится в alertable wait через SleepEx.

Результаты и журналы: results. Только сеанс, соответствующий intervals.csv, относится к успешному итоговому прогону; ранние журналы сохранены как диагностические. fix_clock.py — исторический скрипт изменения формата, повторно запускать не требуется.
